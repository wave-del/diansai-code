# EC 26 E 项目交接手册

本文档面向第一次接手本项目的同学。目标是先在不接触真实执行器的情况下跑通
软件和测试，再逐步接入相机、GPIO、串口和运动机构。

硬件采购、接线、上电和验收请配合阅读 [硬件复刻指南.md](硬件复刻指南.md)。

## 1. 项目是什么

EC 26 E 是一个运行在 A7Z 板端的纸片拼图执行系统。程序从相机图像中定位蓝色
A4 工作区，检测其中的纸片，确认画面稳定后生成移动计划，并通过 XY/Z、旋转轴
和电磁铁完成取放。项目有两种正式任务：

| 任务 | 配置 | 纸片/规划方式 |
| --- | --- | --- |
| Task1 | `configs/tasks/task1.json` | 4 片固定拼图，带图案纸片模式 |
| Task2 | `configs/tasks/task2.json` | 2～4 片随机拼图，白色核心纸片模式 |

主入口只负责加载环境和分派任务；视觉、规划和硬件控制均在独立模块中实现。

## 2. 交接包内容与不包含的内容

交接包同时包含同级的 `vision/` 和 `solver2/`。解压时保留这两个目录相邻，
进入 `vision` 后执行本文的安装、测试和任务命令。包内包含：Python 源码、任务 JSON、部署文件、测试、
示例图片、NPU 模型 `model-bin/`、原生推理库源码及当前板端已构建的
`libyolo11_seg_npu.so`。

为避免带入机器状态，压缩包不包含 `.git/`、`.venv/`、`__pycache__/`、
`.pytest_cache/`、`Testing/Temporary/`、`.vscode/` 及运行时 `outputs/`。`.env`
也不会进入版本库；请从 `.env.example` 复制并按本机重新填写。打包时会保留当前
源码树中已经存在的业务文件和配置，因此发包前应先确认不含密码、令牌或私人录像。

## 3. 目录导览

```text
vision/                     # 同级还必须有 solver2/，其中维护唯一几何算法
├── src/ec_26_e/             # Python 业务包
│   ├── command/             # 唯一 CLI 入口
│   ├── config/              # .env 与任务 JSON 的强类型加载/校验
│   ├── tasks/               # Task1、Task2、按键调度与执行锁
│   ├── vision/              # A4 定位、YOLO/NPU、轮廓精修、稳定器
│   ├── motion/              # XY/Z、F32C 旋转轴、串口协议
│   ├── actuation/           # 电磁铁与 LED
│   ├── cam/                 # FFmpeg/V4L2 相机
│   └── buttons/             # GPIO 按键
├── configs/tasks/           # task1/task2 的正式 JSON 参数
├── native/yolo11_seg_npu/   # YOLO11 分割 NPU 的 C++ C ABI 封装
├── model-bin/               # A733 可执行 NPU 模型
├── deploy/                  # systemd 与桌面快捷方式
├── tools/calibration/       # 现场标定控制台
├── tests/                   # unit、integration 与 external 三类测试
├── docs/                    # 技术说明与本交接文档
└── .env.example             # 板端/硬件环境变量模板
```

阅读代码时建议按这个顺序：`command/app.py` → `tasks/registry.py` →
`tasks/task1/application.py` 或 `tasks/task2/application.py` → `vision/`、
`../solver2/planner.py`、`motion/`。求解算法实现集中在
`../solver2/_engine/`，优先通过 `../solver2/planner.py` 理解输入输出契约。
原 `src/ec_26_e/control` 已删除，任务与测试统一导入 `solver2`。

## 4. 首次安装（不接硬件）

要求 Python 3.10+、Poetry、FFmpeg；板端正式运行还需要 A733 VIPLite/NPU
运行环境、V4L2 相机、串口设备与 GPIO 权限。建议在项目根目录执行：

```bash
poetry install
cp .env.example .env
poetry run ec-26-e --help
```

`--help` 不会读取配置或访问任何硬件。不要直接运行 `ec-26-e` 作为首次验证，
它会根据 `.env` 选择正式任务，并可能打开相机、串口、GPIO 和电磁铁。

先运行无需设备的回归测试：

```bash
poetry run python -m unittest discover -s tests/unit
poetry run python -m unittest discover -s tests/integration
```

如果只修改视觉模块，可使用 README 中列出的三个视觉单元测试。`tests/external/`
下的脚本需要真实设备或录像；它们不是首次安装的必跑项。

## 5. 配置模型

配置分成两层，切勿混用：

1. `.env` 保存“这台机器”的参数：选择任务、相机、串口、GPIO、速度、软件
   限位和 A4 机械原点。
2. `configs/tasks/task*.json` 保存“这个任务”的算法参数：稳定性、A4 定位、
   纸片检测与规划。

加载优先级为：已导出的环境变量 > `.env` > JSON/代码默认值（不同字段的默认
逻辑见对应配置说明）。`EC_TASK` 选择 `task1` 或 `task2`；`EC_TASK_CONFIG`
未设置时自动查找 `configs/tasks/<EC_TASK>.json`。两份 JSON 都是严格
schema 3，未知字段和不合法数值会在启动硬件前拒绝。

最重要的机器参数如下：

| 参数 | 含义 | 修改后必须复核 |
| --- | --- | --- |
| `CAMERA_*` | 相机路径、分辨率、帧率和 FFmpeg | A4 是否完整入画、采集格式 |
| `A4_RESIZE_*` / `WORKSPACE_DETECT_*` | A4 校正和定位分辨率 | 宽高比、性能与定位效果 |
| `MOTION_A4_ORIGIN_*` | A4 原点到电机零点的偏移 | 取放位置和软件限位 |
| `MOTION_*_MIN/MAX_MM` | XY 软件限位 | 所有目标点均在安全范围 |
| `MOTION_MAGNET_GPIO_*` | 电磁铁 GPIO | 实体接线、上下电逻辑 |
| `FOC_*` | F32C 旋转轴 UART/地址/转速 | 与 XY 串口不能混用 |

修改检测或规划阈值前，请先读
[任务1配置说明.md](../configs/tasks/任务1配置说明.md) 和
[任务2配置说明.md](../configs/tasks/任务2配置说明.md)。视觉模型的已知评估范围、
误差和性能数据见 [视觉评估.md](视觉评估.md)。

## 6. 运行流程

正式命令如下：

```bash
# 按 .env 的 EC_TASK 运行
poetry run ec-26-e

# 本次临时选择任务和 JSON；仍会读取其余 .env 机器参数
poetry run ec-26-e --task task2 --task-config configs/tasks/task2.json

# 使用另一个环境文件
poetry run ec-26-e --env path/to/.env
```

运行时主链路是：

```text
.env + JSON → 任务注册表 → 相机最新帧 → 蓝色 A4 校正
→ YOLO 语义门控 + 真实边精修 + 七帧稳定 → 周期稳定审查
→ 拼图规划与坐标转换 → 限位/路径安全校验 → XY/Z/旋转轴/电磁铁执行
→ 失能、释放串口和 GPIO
```

Task1 要求四片稳定纸片并使用 fixed 规划；Task2 使用 random 规划，稳定候选
为 2～4 片时参与规划，超过 4 片则按质量排序取前四片。任务退出码：`0` 成功，
`1` 可预期运行失败，`2` 配置错误，`3` 已有任务占用，`75` 可重试的任务失败，
`130` 用户中断。

## 7. 安全操作顺序

真实硬件必须按以下顺序上线：

1. 断开/禁用执行器，仅运行 `--help` 和 unit/integration 测试。
2. 配好 `.env`，用相机诊断脚本检查画面、分辨率与 A4 四边完整入画。
3. 设置 `EC_DRAW_ENABLED=true` 做只显示预览；确认坐标和纸片轮廓正确。
4. 用 `tests/external/motion/` 中的单轴诊断低速确认方向、零点和限位。
5. 最后才启用电磁铁和正式任务，现场保留急停手段。

Task1 在规划和执行前会检查坐标与限位；这不是替代机械限位、急停和人工看守。
不得把 XY UART `/dev/ttyAS4` 与 F32C UART `/dev/ttyAS3` 配成同一设备。
旋转轴的正式定位是从机械零位顺时针到目标、再逆时针原路回零，不走最短路径。

## 8. 相机、预览与现场标定

真实相机采集和录像示例：

```bash
poetry run python tests/external/cam/record_camera.py --duration 10
poetry run python tests/external/cam/record_detected_video.py
```

后一个命令会保存原始与标注视频；无显示器使用 `--no-preview`。相机画面中蓝色
A4 的四条边必须均在画面内，否则 `Resize` 会主动失败而不会沿用历史角点。

板端桌面入口提供“现场标定”和两个任务预览。标定工作流会编辑 `.env` 和两份
JSON 草稿，只有三者均通过正式强类型校验才会原子切换为生效版本。详细部署文件
见 `deploy/desktop/` 与 `deploy/systemd/README.md`。按键常驻服务使用：

```bash
poetry run ec-26-e --button-service
```

它会串行触发任务并用全局执行锁避免与手工启动并发。

## 9. 原生 NPU 模块

`model-bin/puzzle_seg_yolo11n_640_pcq_a733.nb` 是当前模型；Python 通过
`vision/npu.py` 调用 `native/yolo11_seg_npu/build/libyolo11_seg_npu.so`。当更换
板子、系统或 VIPLite 时，应在目标设备重建原生库：

```bash
cmake -S native/yolo11_seg_npu -B native/yolo11_seg_npu/build -DCMAKE_BUILD_TYPE=Release
cmake --build native/yolo11_seg_npu/build -j4
(cd native/yolo11_seg_npu/build && ctest --output-on-failure)
```

运行时要求 NPU 上下文的创建、推理和销毁在同一线程；不要在没有完整板端依赖的
普通电脑上把 NPU 失败误判为算法失败。

## 10. 常见问题

| 现象 | 优先检查 |
| --- | --- |
| 启动即退出码 2 | `.env` 的 `EC_TASK`、JSON 路径与字段合法性 |
| A4 定位失败 | A4 是否完整入画、蓝纸光照、参考角点和相机分辨率 |
| 没有纸片结果 | 模型/`.so` 是否存在、NPU 环境、`piece_mode`、原图曝光 |
| 任务占用（退出码 3） | 是否已有正式任务或按键服务正在运行 |
| 动作方向/落点错误 | A4 原点、坐标旋转、单轴方向、机械零位，不要先放宽限位 |
| 串口无法打开 | `/dev/ttyAS3`、`/dev/ttyAS4` 权限和设备是否被其他进程占用 |

## 11. 维护约定

- 新任务应新增任务模块、注册项和 JSON，不应在 `command/app.py` 写任务分派分支。
- 改配置字段时同步更新 JSON、强类型加载器、对应 `task*.md` 和测试。
- 改视觉阈值必须记录数据集、光照、模型版本、误报/漏报与性能；不要只凭一次现场
  画面调参。
- 提交前至少跑与改动模块对应的 unit/integration 测试；硬件脚本只在受控环境运行。
- `.env` 是机器私有文件，不能提交；将可共享默认值维护在 `.env.example`。

## 12. 重新制作交接包

在项目根目录执行：

```bash
bash tools/create_handover_archive.sh
```

脚本默认在项目上一级目录生成带日期的 ZIP，同时打包相邻的 `solver2`，并校验完整性。可
传入一个绝对或相对输出路径作为第一个参数。发给后续同学前，建议让对方按第 4 节
完成一次干净安装与测试，确认交接包在另一台机器可解压、可安装、可读文档。
