# 拼图算法更新记录

2026-10-24，参考同级 `fpga-code`（`Cosimo2233/puzzle-solver`，提交 `8123b1f26a5ce85fa192b3cd031ac8085edaf052`）更新本项目。

## 算法与入口

算法直接迁入 `vision/src/ec_26_e/control`，使用本地 `ec_26_e.control` 命名空间；部署时不依赖同级 `fpga-code` 目录。

- 固定四片继续使用模板对应、鲁棒刚体拟合和最终检查，增加轮廓及配对缓存。保留本项目原有的 `FIXED_FINAL_TARGET_TRANSFORMS`，包括 `fixed_piece_1` 的 `(53.0, 189.75)` 最终平移。
- 随机二至四片使用反向边链合并；四片先完整验证整边链提案，再按需展开部分边、多路交点和子装配树。候选通过几何准入及联合优化后进入留缝规划。
- `PlanningOptions.competition_rules=True` 启用 3～5 边、20 mm 最短边（允许显式观测误差）、90～120 × 50～90 mm 结构矩形和整条外边检查。正式随机适配层及 `configs/tasks/task2.json` 已开启；公开库默认关闭以兼容自制短边样品。
- `random_white_solver_adapter.solve_random_white` 调用完整本地引擎，输出原有计划 JSON。调用者可传入误差、候选数量和最低置信度。
- `random_patterned_solver_adapter.solve_random_patterned` 共用同一几何流程。保留 `SceneTextureRanker` 的现场拼缝颜色、梯度连续性评分，以及 Top3 和最终留缝后的实拍复原图。评分只接收通过几何、留缝和运动检查的候选，再由引擎的外观分差及最低接口分数决定是否消歧成功。
- `handover-puzzle/task1_yolo_flow.py` 保持原任务入口和 `MovePlan` 适配，传递实际规划参数。`solver/` 的独立 GUI 实验台仍保留原实现；正式随机任务不再调用其 Beam 搜索。

新引擎不再将不完整矩形或未拼合的原始布局标记为可执行成功。花纹缺失、信息不足或未消歧的候选可保留诊断结果，但不会通过正式随机任务执行检查。

保留可注入的 `RigidFitBackend`、`ClearanceScanBackend` 和 `CandidateScanBackend` 接口，默认使用 CPU；本次未添加 Q6A 或 FPGA 硬件后端实现。最终精确几何和执行检查仍在本地引擎中完成。

## 回归结果

### 现场失败帧的搜索修复及输出门槛

后续以实际第 20691 帧定位并修复了两个问题：正确的三片子装配需要最后合入三角片，
原顺序展开使该分支未获得预算；递归兜底的正确最终候选按局部代价排第 64，
超过前 48 项截断。现在四个分支轮流展开，完整装配在截断前按矩形质量优先排序。

正式 planner 和白色/花纹适配层默认不设时间上限，网页固定/随机任务也取消了
内部和外部超时。库中的显式有限预算仍可用于离线对照。`unlimited_search=true`
时内部不再设置各搜索分支的秒数上限，诊断中的 deadline 输出 `null`。

输出前硬性检查留缝前的矩形填充率至少 95%；低于门槛返回失败及空 moves。
填充率取实测轮廓拼合并集面积与最小外接矩形面积之比。固定模式先在拟合的模板
坐标中测量，再使用现场静态落位；随机模式在求出的紧密拼合坐标中测量。
输出的 `rectangle_fill_ratio` 和 `planned_rectangle_fill_ratio` 分别表示拼合及留缝后的占比。

网页增加 `/api/solve/cancel` 和“取消求解”按钮，取消时终止独立求解进程组，
任务结束前禁用重新提交，取消完成后可重新计算；取消请求带任务 ID，避免误停后续任务。

本轮控制模块回归 84 项通过，另有 2 项输出门槛边界测试通过；两个历史固定模板
断言仍失败。网页 19 项测试、正式适配层 9 项测试、原流程接线 10 项测试通过。
新增真实失败帧的四种输入顺序回归，及启动前/运行中/完成瞬间取消和 HTTP 取消检查。

### 第 2489 帧的花纹选优修复

后续现场帧虽然达到 96.15% 几何填充率，上方子拼图仍存在图案方向错误。
网页原先使用 white 分支，首次达标就停止，几何通过不能证明印刷图案连续。

正式适配层现在收集多个不同的安全拼法；2 mm 观测量级内的整体旋转/平移及轻微
重拟合视为同一拼法，单片发生独立旋转仍保留。对于四片各含外框角点的情况，
从实测角点额外生成刚体提案；其它切法继续使用通用边链路径，不读取参考真值。

花纹沿相对的实测边分别采样，允许有限的轮廓误差和小范围像素配准。
评分同时约束平均接缝和最弱整条接缝；确认还要求有效纹理、覆盖所有碎片的
可比较接缝图、最低连续性及候选分差。所有评分只影响选优，不改变电机目标坐标。

网页随机任务会检查冻结画面内的实际纹理；纯白纸片和平滑照明渐变不会作为印刷图案。
`solved` 仅表示花纹完成确认；`geometry_only` 明确表示仅几何达标，不能宣称牌面已接对。
95% 输出门槛、无时间上限和进程组取消机制继续生效。

第 2489 帧回放比较了 3 个不同几何达标候选，选中填充率 97.91% 且图案连续的方案；
第 20691 帧也完成花纹确认，填充率 98.55%。新添真实正误拼法评分、候选去重、
角点提案刚体闭合、空白渐变图及完成确认标记的回归。

本次重载网页后，实时 HTP 初始化出现 `deviceCreate failed: 0x36b1`，干净进程
重试仍报 CDSP/FastRPC 传输失败。恢复 RPC 服务后通信仍阻塞，随后仅软重启 CDSP
固件并恢复 RPC 服务，真实 HTP 推理恢复，约 7.9 ms/帧。连续帧及取消接口已复验，
未进行 CPU 模型回退；完整验证记录保存在网页 acceptance 的 pattern-selection 报告中。

## 复现

在 `diansai-code` 根目录执行；两个测试目录各自带有 `tests` 包，需要分别运行：

```bash
(cd vision && PYTHONPATH=src ../.venv/bin/python -m pytest tests/unit/control -q)
PYTHONPATH=vision/src:handover-puzzle .venv/bin/python -m pytest tests/test_reference_algorithm.py -q
(cd vision && PYTHONPATH=src ../.venv/bin/python -m pytest tests/unit/test_task2_config.py::Task2ConfigTest::test_official_planner_enables_reference_competition_rules tests/integration/tasks/test_task2_application.py -q)
PYTHONPATH=vision/src:handover-puzzle .venv/bin/python handover-puzzle/test_task1_yolo_flow.py
```

第一条命令仍会报告上述两个固定模板失败。迁入的真实混合边数、尺寸边界和候选优先级样例保存在 `tests/fixtures/poker_*.json`；批量后端回归使用 `tests/fixtures/fixed4_reference.json`。
